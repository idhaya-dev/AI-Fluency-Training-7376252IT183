
# Day 3 Assignment: Plain LLM vs LLM with a Tool

## 1. Scenario

The scenario selected for this assignment is a Course Fee Advisor. The purpose of this project is to compare a plain Large Language Model (LLM) with an LLM connected to an external tool.

The system helps users find the fees of courses using their course codes. The course fee information is stored in a Python dictionary in the program.

The dictionary contains the following course details:

| Course Code | Course Fee |
|---|---:|
| CS101 | ₹30,000 |
| AI202 | ₹40,000 |
| DS303 | ₹35,000 |

Two approaches are implemented in this assignment.

The first approach uses a plain LLM without access to the course fee dictionary. The second approach uses an LLM connected to a Python function called `get_course_fee()`, which retrieves the exact fee from the dictionary.

The same scenario is used to observe how both approaches respond to general questions and questions requiring private course fee information.

## 2. Explanation of Concepts

### 2.1 Large Language Model (LLM)

A Large Language Model (LLM) is an artificial intelligence model trained on a large amount of text to understand language and generate human-like responses.

An LLM can answer general questions, explain concepts, summarize information, and generate text based on its training and the context provided to it.

However, a plain LLM cannot automatically access private information stored in a local Python program or database unless that information is provided to it.

In this assignment, the plain LLM receives the question, "What is the fee for AI202?" Since it does not have access to the course fee dictionary, it cannot retrieve the exact fee stored in our program.

### 2.2 Agent

An AI agent is a system that uses an LLM to understand a user's request and decide what action to perform.

An agent can use external tools to obtain information or perform tasks that the LLM cannot complete using its existing knowledge alone.

In this project, the tool-enabled LLM acts as a simple agent. It understands the user's question, decides to call the course fee lookup tool, receives the result, and generates a final response.

The agent combines the language understanding ability of the LLM with the data retrieval ability of the Python function.

### 2.3 Tool and Tool Call

A tool is an external function or program that an LLM can use to perform a specific task.

A tool call is a structured request generated by the LLM to use an available function. The request contains the tool name and the arguments required by the function.

The tool used in this assignment is `get_course_fee()`, which is defined in `tools.py`.

It accepts a course code as input and searches for the corresponding fee in the course fee dictionary.

For example:

`get_course_fee("AI202")`

The function returns:

`The fee for AI202 is ₹40,000.`

If the course code does not exist in the dictionary, the function returns a message stating that the course was not found.

The LLM does not execute the Python function directly. Instead, it requests the tool call, and the Python program executes the function and returns its result to the model.

### 2.4 One Tool Call Step-by-Step

The tool-calling process in this assignment works as follows.

**Step 1: User asks a question**

The user asks, "What is the fee for AI202?"

The question is sent to the LLM along with the available tool definition.

**Step 2: LLM identifies the required tool**

The LLM understands that the user is asking for a specific course fee.

Since the fee is stored in the Python dictionary, the model decides to call the `get_course_fee` tool.

**Step 3: LLM generates a tool call**

The model generates a structured request containing the tool name and argument.

Tool name: `get_course_fee`

Argument: `course_code = "AI202"`

**Step 4: Python executes the tool**

The Python program receives the tool call and executes:

`get_course_fee("AI202")`

The function searches the dictionary and returns the fee of ₹40,000.

**Step 5: Tool result is sent back to the LLM**

The Python program sends the tool result back to the model as a tool message.

The LLM uses this result to prepare a response for the user.

**Step 6: LLM generates the final answer**

The LLM generates a natural-language response based on the tool result.

The final answer communicates that the fee for AI202 is ₹40,000.

This process allows the LLM to provide information retrieved from an external function instead of relying only on its existing knowledge.

### 2.5 Why Tools Return Plain Text

Tools return their results as text because the LLM can easily understand and process textual information.

A tool can return a number, a message, or other information converted into text. The result is sent back to the LLM, which uses it to generate a response.

In this project, the course fee lookup function returns a string containing the course code and fee.

For example:

`The fee for AI202 is ₹40,000.`

The text is sent back to the LLM, which uses it to prepare a natural-language answer.

Returning plain text makes communication between the tool and the LLM simple and allows the model to explain the result to the user.

## 3. Comparison Table

| Feature | Plain LLM | LLM with Tool |
|---|---|---|
| External tool access | Not available | Available |
| Access to private course fee data | No direct access | Access through the lookup function |
| Exact fee retrieval | Cannot retrieve the stored fee unless the data is provided | Retrieves the stored fee using the Python function |
| Tool execution | No external function is executed | Python executes the requested function |
| Response generation | Based on model knowledge and provided context | Based on the tool result and language model |
| General questions | Can answer without a tool | Can answer without calling the tool |
| Suitable for | General questions and explanations | Questions requiring external or private data |

## 4. Test Questions and Results

Three questions were used to compare the plain LLM and the tool-enabled LLM.

The questions include general knowledge and course fee lookup tasks.

### 4.1 Question 1: What is the fee for AI202?

**Plain LLM:**

The plain LLM did not have access to the course fee dictionary. It asked for additional information about the institution or program instead of providing the exact stored fee.

**LLM with Tool:**

The tool-enabled LLM identified that the question required a course fee lookup.

It called `get_course_fee()` with the argument `AI202`.

The tool returned the exact fee of ₹40,000, and the LLM used the result to generate the final answer.

**Observation:**

The tool-enabled approach retrieved the private course fee information, while the plain LLM could not access it directly.

### 4.2 Question 2: What is a database?

**Plain LLM:**

The plain LLM can answer this general question using its existing knowledge without accessing an external tool.

A database is an organized collection of data that can be stored, accessed, managed, and updated.

**LLM with Tool:**

The tool-enabled LLM can also answer this question without calling the course fee lookup tool because the question does not require course fee information.

**Observation:**

Both approaches can answer general questions without requiring the course fee tool.

### 4.3 Question 3: What is the fee for DS303?

**Plain LLM:**

The plain LLM does not have access to the private course fee dictionary. Therefore, it cannot reliably retrieve the exact fee stored in the program.

**LLM with Tool:**

The tool-enabled LLM identifies the requirement for a course fee lookup and calls `get_course_fee()` with the argument `DS303`.

The tool returns:

`The fee for DS303 is ₹35,000.`

The LLM uses this result to generate the final answer.

**Observation:**

The tool-enabled approach retrieves the exact fee from the dictionary, while the plain LLM does not have direct access to the stored information.

## 5. Overall Observations

The experiments show that the plain LLM and the tool-enabled LLM have different capabilities.

The plain LLM can answer general questions using its existing knowledge. However, it cannot automatically access private information stored in the local Python program.

The tool-enabled LLM can identify when external information is required and request the appropriate tool. The Python function retrieves the exact information and returns it to the LLM.

For the AI202 and DS303 fee questions, the tool-enabled approach retrieved the stored fees of ₹40,000 and ₹35,000 respectively.

For the general question about databases, the course fee tool was not necessary because the LLM could answer using its existing knowledge.

The experiments demonstrate that tools extend the capabilities of an LLM by providing access to external information and functions.

## 6. Suitability

### 6.1 Plain LLM

A plain LLM is suitable for general questions, explanations, summarization, and tasks that do not require access to external or private information.

It can generate useful responses without executing external functions.

However, it may not provide accurate answers to questions requiring private data that has not been included in its context.

### 6.2 LLM with Tool

An LLM connected to a tool is suitable for tasks that require accurate information from databases, files, APIs, or other external sources.

In this assignment, the course fee lookup tool provides access to the fee dictionary, allowing the system to answer course fee questions using the stored data.

This approach can also be extended to other applications such as student information systems, inventory management, and database query systems by connecting suitable tools.

## 7. Conclusion

This assignment compares a plain LLM with an LLM connected to an external tool using a Course Fee Advisor scenario.

The plain LLM answers general questions using its existing knowledge but cannot directly retrieve private course fee information stored in the Python dictionary.

The tool-enabled LLM identifies when a tool is required, calls the `get_course_fee()` function, receives the result, and generates a final answer based on the retrieved information.

The experiments show that general questions can be answered without tools, while questions requiring private course fee information benefit from tool access.

In conclusion, combining an LLM with external tools extends its capabilities and allows it to retrieve specific information that is not available in its existing context.
